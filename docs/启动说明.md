# SmartSchedule 启动说明

这个项目已经不是"前端一个终端、后端一个终端、还要先开数据库"的那种启动了。
现在只有一个 jar，里面自带页面和 H2 数据库文件，双击一下就好。

## 用起来（日常只有这一步）

双击桌面上的 **SmartSchedule** 快捷方式，或者在项目根目录双击 `start.cmd`。

它会做这几件事：

1. 先检查 8080 端口是不是已经有服务在跑——已经在跑就直接打开浏览器，不会起第二个；
2. 没找到 jar 就自动构建一次；
3. 后台启动服务，等它起来后打开 http://localhost:8080/today

窗口里只会闪几下，然后浏览器就开了。服务在后台跑，关掉那个黑窗口不影响。

## 停下来

双击项目根目录的 `stop.cmd`，或者直接在任务管理器里结束 java.exe。

## 改了代码之后

双击 `build.cmd`：先构建前端（npm run build），再打成 jar（mvn package）。
跑完 `backend\target\smart-schedule-1.0.0.jar` 就是新的，下次 `start.cmd` 用的就是它。

不想用脚本也行：

```
cd frontend && npm run build
cd backend && mvn -DskipTests package
```

## 文件都在哪

| 东西 | 位置 |
| --- | --- |
| 程序 | `backend\target\smart-schedule-1.0.0.jar` |
| 数据库 | `%LOCALAPPDATA%\SmartSchedule\data\smartschedule.mv.db` |
| 启动日志 | `%LOCALAPPDATA%\SmartSchedule\logs\app-日期.log` |
| 页面源码 | `frontend\src` |
| 接口 | http://localhost:8080/api |

数据库是 H2 的文件库，不用装 MySQL，也不用开 Docker。

## 出问题了看这里

**窗口提示"没找到 java"**
装一个 JDK/JRE 8 以上，装完确认新开的窗口里 `java -version` 能出来。

**等 90 秒服务还是没起来**
窗口里会自动打出日志最后 20 行，也可以直接看上面那个 logs 目录。
常见原因：
- 8080 被别的程序占了（`netstat -ano | findstr :8080` 看是谁）；
- 上一次的 java 进程没退干净，数据库文件被锁住——先跑一次 `stop.cmd` 再启动。

**端口想换**
改 `backend\src\main\resources\application.yml` 里的 `server.port`，
然后 `build.cmd` 重新打包，同时把 `start.cmd` 里的 8080 一起改掉。

**登录不进去**
默认账号 `demo` / `demo123`。

## 关于 AI 生成任务书

生成任务书要调 DeepSeek。**key 不在仓库里**：它放在
`%LOCALAPPDATA%\SmartSchedule\config\application-local.yml`（即 `C:\Users\<你>\AppData\Local\SmartSchedule\config\application-local.yml`），
由 `application.yml` 里的 `spring.config.import` 读进来；仓库里只有占位符 `${DEEPSEEK_API_KEY:}`。

换 key 就改那个文件，改完重启（`stop.cmd` → `start.cmd`）。没有这个文件也能启动，
只是 AI 生成会退回本地模板（任务书仍是完整可用的，只是内容不是 AI 写的）。
用的是 `deepseek-chat`（不要换成带思考过程的型号，它会把 JSON 写到推理字段里，容易截断）。
