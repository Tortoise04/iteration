# SmartSchedule · 任务书改造契约（唯一标准）

> 本文件是后端与前端两个实现包的共同契约。任何与本文件冲突的实现，以本文件为准；
> 本文件没写到的细节自行判断，但不得改动本文件已定的字段名、路径、语义。

## 0. 目标（一句话）

把"一天一条时间线"改成"一本任务书带着你走完一个目标"：选目标 → AI 生成整本任务书（周分段、天拆条，每条写清做什么/学什么/多久/算完成）→ 人工改 → 确认 → 每天在「今天」页执行，没做完自动顺延重排。

用户已确认的范围决策（不要再改）：
1. 保留 Spring Boot + Vue 技术栈，只加任务书主线；前端打进 jar、数据库换内嵌 H2、一键启动。
2. 任务书来源：AI 生成整本 → 用户编辑 → 确认 → 逐日执行。
3. 条目没做完：标未完成 → 剩余自动顺延、整体重排。
4. 只砍"休息块当待办"（BREAK 任务不再生成、不再下发）；积分、课表、OCR、AI 对话全部保留。
5. 首页改成「今天」；原单日看板降级为「时间线」页。
6. 不做 Word/PDF 导出。

## 2. AI 生成契约

`AiService` 新增 `generateTaskBookJson(goal, startDate, endDate, extraContext)`，走 OpenAI 兼容 `/chat/completions`，
**默认模型用 `deepseek-chat`**（`deepseek-v4-pro` 是推理模型，reasoning 会吃掉 token 导致 JSON 截断；
配置项新增 `app.ai.deepseek.taskbook-model`，默认 `deepseek-chat`，max_tokens 8192，temperature 0.4）。

要求 AI 返回且只返回 JSON（外层允许 ```json 代码块，解析前剥掉）：

```json
{
  "title": "英语四级·12月冲刺任务书",
  "purpose": "2-4 句，说明为什么这样排、预期达到什么水平",
  "requirements": "总要求，3-6 条，用换行分隔",
  "weeks": [
    {
      "weekIndex": 1,
      "theme": "听力打底",
      "focus": "每天精听 1 篇 + 背词 50",
      "startDate": "2026-10-21",
      "endDate": "2026-10-27",
      "items": [
        {
          "planDate": "2026-10-21",
          "title": "四级听力精听",
          "learnContent": "2019.12 第一套 Section A 短篇新闻 3 篇，听 2 遍后逐句跟读",
          "estMinutes": 45,
          "doneCriteria": "3 篇能在不暂停下复述大意，生词进生词本",
          "category": "STUDY"
        }
      ]
    }
  ]
}
```

硬性要求（写进 prompt，也要在服务端校验/兜底）：
- 周必须覆盖 `startDate..endDate` 整段，最后一周可以不满 7 天；日期不得越界。
- 每个有课/有安排的日子 **每天 1-3 条**；允许周末空一天（不排条目不报错）。
- **禁止生成吃饭、睡觉、休息、通勤类条目**。
- `learnContent` 必须具体（材料名/章节/题量/单词数），禁止"学习英语""复习一下"这类空话；校验失败按空内容处理。
- AI 失败/JSON 解析失败 → 走**确定性兜底生成**：按周切片、每周一个主题（第 N 周·推进），每天按 1-2 条生成
  "做什么/学什么"的模板条目（用目标名 + 周序号 + 目标描述拼装），保证接口永远返回可用任务书，并在响应里带
  `"aiGenerated": false`。

## 3. REST 契约（一律 `/api/taskbooks`）

所有接口需要 JWT（沿用现有 `Authorization: Bearer`）。返回统一沿用现有风格：直接返回 DTO/实体 JSON，错误走 `GlobalExceptionHandler`。

| 方法 | 路径 | 请求 | 返回 |
| --- | --- | --- | --- |
| POST | `/api/taskbooks/generate` | `{ "goalId": 1, "startDate": "2026-10-21" }`（startDate 可省，默认今天） | 完整任务书详情（见下），status=DRAFT，含 `aiGenerated` |
| GET | `/api/taskbooks` | — | `[{ id, title, goalId, goalName, startDate, endDate, status, totalItems, doneItems }]` |
| GET | `/api/taskbooks/{id}` | — | 完整详情：`{ id, title, purpose, requirements, goalId, goalName, startDate, endDate, status, progress:{done,total}, weeks:[{ id, weekIndex, theme, focus, startDate, endDate, items:[...] }] }` |
| PUT | `/api/taskbooks/{id}` | `{ title?, purpose?, requirements? }` | 完整详情 |
| PUT | `/api/taskbooks/{id}/status` | `{ "status": "CONFIRMED" \| "ARCHIVED" \| "DRAFT" }` | 完整详情 |
| PUT | `/api/taskbooks/items/{itemId}` | `{ title?, learnContent?, estMinutes?, doneCriteria?, planDate? }` | 更新后的 item |
| PUT | `/api/taskbooks/items/{itemId}/status` | `{ "status": "DONE" \| "PENDING" \| "DROPPED" }` | `{ item, rescheduled: [{ itemId, planDate }] }` |
| POST | `/api/taskbooks/items/{itemId}/defer` | — | `{ item, rescheduled: [...] }`：把这一条顺延到最近的可用日 |
| POST | `/api/taskbooks/reschedule` | — | `{ moved: [{ itemId, from, to }] }`：把**所有**逾期未完成条目顺延 |
| POST | `/api/taskbooks/{bookId}/items` | `{ planDate, title, learnContent?, estMinutes?, doneCriteria?, category?, weekId? }` | 新建条目（origin_date=planDate、status=PENDING、sort_order=当天最大值+1） |
| DELETE | `/api/taskbooks/items/{itemId}` | — | `{ deleted: true }` |
| GET | `/api/taskbooks/today?date=yyyy-MM-dd` | date 可省=今天 | 见 3.1（**只读，不改数据**） |

item 的 JSON 字段：`id, bookId, weekId, planDate, originDate, title, learnContent, estMinutes, doneCriteria, category, status, deferCount, sortOrder`。
日期一律 `yyyy-MM-dd`（Jackson 已配 `yyyy-MM-dd HH:mm:ss`，DATE 字段需 `@JsonFormat(pattern="yyyy-MM-dd")` 或返回 String，前端按字符串处理）。

### 3.1 `GET /api/taskbooks/today`

```json
{
  "date": "2026-10-21",
  "books": [
    { "bookId": 1, "title": "英语四级·12月冲刺任务书", "theme": "听力打底",
      "items": [ { "id": 12, "title": "四级听力精听", "learnContent": "...", "estMinutes": 45,
                   "doneCriteria": "...", "category": "STUDY", "status": "PENDING", "deferCount": 1 } ] }
  ],
  "behind": { "count": 3, "items": [ { "itemId": 7, "bookId": 1, "title": "...", "originDate": "2026-10-19", "planDate": "2026-10-21", "deferCount": 2 } ] },
  "progress": { "done": 12, "total": 40 }
}
```

- 只看 `status=CONFIRMED` 的任务书。
- `behind` = 该用户所有 `plan_date < today` 且 `status=PENDING` 的条目。
- `progress` = 所有 CONFIRMED 任务书的完成度。

## 4. 顺延算法（必须与本节一致）

触发点：`PUT items/{id}/status`、`POST items/{id}/defer`、`POST /api/taskbooks/reschedule`、**确认任务书时**（`status→CONFIRMED`）。
**前端在「今天」页加载时先 `POST /api/taskbooks/reschedule` 再 `GET /api/taskbooks/today`。**

算法（只处理 `status=PENDING` 的条目）：
1. 每日容量：同一本任务书同一天最多 **3** 条（已 DONE 的也占位）。
2. 候选集：`plan_date < today` 的 PENDING 条目 + 被显式 defer 的那一条。
3. 按 `(origin_date, sort_order)` 升序逐条处理：从 `max(today, 当前 plan_date + 1)` 起找第一个未满的日期 `d`，
   要求 `d <= book.end_date`；找到则 `plan_date = d`、`defer_count += 1`。
4. 若 `book.end_date` 之前都满了：放到 `book.end_date`（允许当天超过 3 条），`defer_count += 1`。
5. `DONE` / `DROPPED` 永不移动；`origin_date` 永不改写。
6. 幂等：没有逾期条目时返回空 `moved` / `rescheduled`。

需要一条 JUnit 测试覆盖：逾期两条、当天已有 3 条、跨周、endDate 已满 四种情况。

## 5. 休息块移除

- `ScheduleService` 生成日程时不再创建 `taskType=BREAK` 的 `DailyTask`（AI 返回的休息块直接丢弃；贪心兜底里删掉休息块插入）。
- `/api/schedule/today`、`/api/schedule/history` 返回时过滤掉历史遗留的 BREAK 任务。
- 前端不再渲染 BREAK 任务（双保险）。

## 9. 实现记录（2026-10-21 落地，实测确认）

- **端点补充**：`POST /api/taskbooks/{bookId}/items`（body: planDate / title / learnContent / estMinutes / doneCriteria / category）、`DELETE /api/taskbooks/items/{itemId}`（重复删除返回 404）。
- **行为偏差**：`POST items` 传入的 planDate 若早于今天，落库时被纠正为今天（新条目不允许建在过去）；逾期条目的正确处理路径仍是 §4 的 reschedule。
- **today 响应**：date / books / behind / progress 均在顶层，progress 不嵌套在 book 内。
- **顺延实测**：今日容量 3、DONE 占位成立（今天 1 条 DONE 时只再接受 2 条，其余落次日）；DONE 不被移动；重复调用返回 `{"moved":[]}`。
- **SPA 回退**：仅无扩展名的前端路由回退 index.html；`/assets/*.js` 不存在返回 404（application/json），不乱回退。
- **启动方式**：根目录 `start.cmd` / `stop.cmd` / `build.cmd` / `create-shortcut.cmd`，日志 `%LOCALAPPDATA%\SmartSchedule\logs\app-日期.log`。
- **测试**：38 个全绿。原 `ScheduleServiceTest.testGeneratePlan_SingleGoal_AllocatesTask` 的 stub 由写死 60 分钟改为 anyInt，断言值 18（60 分钟目标被贪心切成两个 30 分钟 slot）。
